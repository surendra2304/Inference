# 🗓️ AI Universe — 24 August 2026

**Day 1 &nbsp;·&nbsp; Foundation, 7-Provider Gateway & 10 Specialist Agents**

---

Today I started AI Universe from zero. The core idea is simple but ambitious — instead of asking a single AI model for an answer, I wanted to build a team of specialist AI agents that each analyze a problem from their own angle and then collectively arrive at a better, more reliable answer. Think of it like assembling a panel of experts instead of consulting one generalist.

I started by designing the project structure and setting up `pyproject.toml` with the core dependencies: FastAPI as the server, Uvicorn as the ASGI runtime, httpx for async HTTP calls to cloud providers, Pydantic for structured data validation, and aiosqlite for async SQLite reads and writes.

---

### Setting Up the Multi-Provider Gateway

The first major thing I built was the multi-provider gateway. The idea is that AI Universe shouldn't depend on a single cloud AI provider — if one is slow, throttled, or down, it falls back to another one automatically. I connected 7 permanently free cloud LLM providers:

- **Google Gemini** (`gemini-2.5-flash`, `gemini-2.0-flash`) — primary fast reasoning provider.
- **Groq** (`llama-3.3-70b-versatile`) — ultra-low latency inference via Groq's proprietary hardware.
- **Mistral AI** (`mistral-small-latest`) — strong at precise factual reasoning and security analysis.
- **OpenRouter** (`nvidia/nemotron-3.5-lightning:free`) — free-tier routing layer over multiple model hosts.
- **NVIDIA NIM** (`meta/llama-3.1-8b-instruct`, `meta/llama-3.1-70b-instruct`) — NVIDIA's hosted inference endpoints.
- **Cohere** (`command-r-plus`, `command-r7b-12-2024`) — excellent at synthesis and long-context comprehension.
- **HuggingFace** (`meta-llama/Llama-3.3-70B-Instruct`) — open model access via HuggingFace Inference API.

Each provider got its own adapter class inheriting from `BaseLLMProvider` in `app/providers/base.py`. All adapters implement a unified `generate()` async method that accepts a `ProviderRequest` and returns a `ProviderResponse`. This abstraction means the rest of the system doesn't care which cloud is actually doing the work — it just calls `get_provider("groq").generate(req)` and gets a response back.

I also wired up `.env` loading via Pydantic Settings in `app/core/config.py` so API keys are never hardcoded anywhere. I created `.env.example` showing every required variable with placeholder values so anyone cloning the repo knows what to set.

One early decision was removing Cloudflare Workers AI before it could waste time. I tested it briefly and the latency was inconsistent — it wasn't worth being in the rotation.

### Designing the 10 Specialist Agent Roles

With the providers connected, I built the agent layer. I registered 10 specialist agent personas in `app/agents/roles/` and `app/agents/registry.py`, each with a unique domain focus, assigned model, and custom system prompt that frames how they approach a problem:

| Agent | Provider | Model |
| :--- | :--- | :--- |
| **Researcher** | Gemini | `gemini-2.5-flash` |
| **Architect** | Groq | `llama-3.3-70b-versatile` |
| **Coder** | HuggingFace | `meta-llama/Llama-3.3-70B-Instruct` |
| **Debugger** | NVIDIA | `meta/llama-3.1-8b-instruct` |
| **Security Analyst** | Mistral | `mistral-small-latest` |
| **Data Analyst** | OpenRouter | `nvidia/nemotron-3.5-lightning:free` |
| **Critic** | Groq | `llama-3.3-70b-versatile` |
| **Fact Checker** | Mistral | `mistral-small-latest` |
| **Strategist** | NVIDIA | `meta/llama-3.1-70b-instruct` |
| **Synthesizer** | Cohere | `command-r-plus` |

The registry (`InMemoryAgentRegistry`) supports `register_agent()`, `get_agent()`, `list_agents()`, and `get_agents_by_capability()` so the orchestrator and router can dynamically look up which agents are best suited for a given task type.

### Building the SQLite Memory Subsystem

I wanted everything AI Universe does to be locally persisted and auditable, so I built the SQLite memory layer in `app/memory/sqlite.py`. It uses `aiosqlite` for non-blocking async database access and creates the following tables on startup:

- **`agents`** — stores the registered agent configurations (id, name, role, provider, model, status).
- **`tasks`** — records every incoming question with its mode, status, and final result.
- **`runs`** — audit trail for every individual agent call: which agent ran, on which provider, which model, what latency, how many tokens, and whether it succeeded or failed.
- **`messages`** — stores the full content of every message exchanged between agents in a run, scoped by task and stage.
- **`memories`** — scoped per-agent persistent memory for facts and learned context, with importance scoring.
- **`strategies`** — stores learned routing strategies: for a given task type, which agents and providers performed best.
- **`experiments`** — logs architectural hypothesis tests and their outcomes.
- **`evaluations`** — stores quality scores and feedback for completed runs.

I added proper indexes on `agent_id`, `task_id`, and `status` columns to keep queries fast as the database grows.

### Implementing the First Debate Engine

With agents registered and memory working, I built the first version of the multi-agent debate engine in `app/agents/debate.py`. This initial version was a structured 6-round protocol:

1. **Problem Framing** — Researcher identifies the core technical question.
2. **Independent Analysis** — Specialist agents generate their own perspectives.
3. **Cross-Review** — Agents review and comment on each other's proposals.
4. **Rebuttal** — Agents defend or revise their positions.
5. **Evidence Check** — Fact Checker validates claims.
6. **Final Synthesis** — Synthesizer merges everything into a unified final answer.

It was functional but heavy — every query went through all 6 rounds regardless of whether the agents actually disagreed. That was the trade-off I knew I'd have to fix later.

I also built the FastAPI application shell in `app/main.py`, registered the routes, set up the `Orchestrator` in `app/core/orchestrator.py` with smart task routing in `app/agents/router.py`, and wired the whole thing together.
