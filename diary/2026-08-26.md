Today I fixed a fundamental architectural flaw in how the orchestrator handled API requests from FRIDAY and Forge.

---

### The Problem I Discovered

When FRIDAY or `scripts/ask.py` sent a question to AI Universe, the orchestrator was routing it to `fast` mode because the question was short. And in `fast` mode, it was just calling a **single agent directly** — no collaboration, no parallel thinking, nothing. The whole multi-agent system was being bypassed entirely. The `CollaborationEngine` was only ever being called when the mode was explicitly `debate`.

So FRIDAY was effectively just hitting one LLM provider with one agent and getting back a single response. That completely defeats the purpose of building a multi-agent system.

---

### The Fix: Unified CollaborationEngine for All Modes

I removed the separate single-agent code path from `app/core/orchestrator.py` entirely. Now **every request** — regardless of whether it's `fast`, `review`, or `debate` — goes through the `CollaborationEngine`. The only difference is how many agents get assembled:

- **`fast` mode** — 2 agents in parallel: the best domain specialist for the question (detected by the task router) + the Synthesizer. They think simultaneously, and the Synthesizer merges their perspectives instantly.
- **`review` mode** — 3 agents in parallel: the router-selected pair + a cross-checking specialist (Fact Checker, Critic, or Strategist depending on availability). Same instant synthesis.
- **`debate` mode** — the full 3-5 agent panel selected by the debate panel selector, same as before.

The `CollaborationEngine` itself already handles everything internally — if the agents align, it does instant consensus (`mode_used = "consensus"`). If there's a genuine contradiction or security risk, it triggers a targeted rebuttal (`mode_used = "debate"`). That logic didn't change at all.

This means every call FRIDAY makes now gets real multi-agent collaborative reasoning instead of a single LLM call.

### The `live_debate.py` Script Stays As-Is

The full 10-agent adversarial panel in `scripts/live_debate.py` is separate and intentional — it's the manual/demo mode where all 10 specialists analyze the question in parallel and you can read each one's perspective. That's meant to be used manually to see the full system at work. It's not affected by this change.

### Ultimate Provider Gateway & Dynamic OpenRouter Capability Fallback

Implemented a high-resilience Gateway architecture across all cloud providers:
- **Global Key Pool & Round-Robin Rotation** (`app/providers/gateway.py`): Supports comma-separated keys with automatic 60s quarantine upon HTTP 429/503 errors.
- **Isolated Per-Provider Rate Limiting**: Token-bucket limiters guarantee that throttling on one provider never blocks or delays requests to others.
- **Provider Health Tracking** (`app/providers/health.py`): Live tracking of success rates, average latency, and 429 frequency with dynamic health scoring.
- **Dynamic Capability-Based OpenRouter Fallback** (`app/providers/openrouter.py`):
  - Added `get_best_free_model(capability: str)` to query OpenRouter's live `/api/v1/models` endpoint for `:free` models dynamically matching specific capability tags (`coding`, `reasoning`, `research`, `analysis`, `security`, `general`).
  - When primary providers exhaust their key pools or fail, the Gateway seamlessly routes to the best matched OpenRouter free model.

### Dynamic DAG Orchestrator & 10 Specialist Hyper-Specialized Models

- Configured all 10 specialist agents with ranked model lists and capability tags in `app/agents/roles/__init__.py`.
- Built the **Dynamic DAG Orchestrator** (`app/core/dag.py` and `app/core/orchestrator.py`):
  - Classifies tasks by complexity (`SIMPLE`, `COMPLEX`, `STRATEGIC`).

  - Health checks dynamically skip rate-limited providers before making calls.
